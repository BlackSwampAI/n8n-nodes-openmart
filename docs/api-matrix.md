The production origin is fixed at `https://api.openmart.ai`, with recommended `Authorization: Bearer <api_key>` authentication. Business Search exposes only `has_website`, `has_valid_website`, `has_contact_info`, and positive-integer `min_locations`; blank location fields are omitted. Company Search is one row per brand, while Business Search targets local/store-level leads. For US locations, two-letter state codes such as `CA` or `OH` are recommended without rejecting non-US region names. Company Enrich matches existing Openmart records rather than crawling arbitrary websites. Tags and broader endpoint fields remain deliberately absent.

All advertised operations use n8n declarative routing and make one request per input item without hidden retries. Users may opt into standard n8n retry settings for safe reads. Search and paid creation are not retried internally. Enabling n8n Retry On Fail or manually rerunning paid creation can create duplicate charged work.

For 0.1.0, the shared Batch Status → Task IDs → Task Get retrieval chain and a demonstrated Search → email/contact discovery → downstream data handoff are release-critical, with fixtures and workflow evidence for both branches where appropriate. The node provides data but does not send outreach. Company Emails means generic shared inboxes; Find Decision Makers means named individual contacts and emails.

Future-release/backburner operations, not implemented or advertised, are: Business Get; Detect Tech Stack; Search Business IDs Fast; Get by Google Place ID; Create Deny Rules; Check Deny Rules; Delete Deny Rules.
